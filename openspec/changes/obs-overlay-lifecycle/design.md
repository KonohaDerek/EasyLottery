## Context

Donate OBS 目前每兩秒讀取該活動最後一筆抽獎紀錄，沒有區分頁面載入前的歷史紀錄與剛送達的通知；因此重新載入頁面會立即顯示舊結果。所有 OBS 路由共用同一個版面，但全域網頁背景和部分空狀態文字仍會被輸出到擷取來源。Donate 活動已有事件溯源與 YAML 快照，新增可保存的活動設定必須經過正規化、事件投影與舊資料預設值處理。

## Goals / Non-Goals

**Goals:**

- Donate OBS 初次連線只建立目前最新紀錄的游標，不渲染既有結果。
- 新紀錄到達後依活動設定顯示有限秒數，再回到沒有任何內容的透明待機狀態。
- 讓結果顯示秒數可在 Donate 活動編輯視窗保存，並在快照與事件重播後一致保留。
- 所有 OBS 路由的全域背景、載入與無效設定狀態均保持透明且無待機文字。

**Non-Goals:**

- 不刪除歷史 Donate 抽獎紀錄，亦不改變報表資料。
- 不更改轉盤、戳戳樂或加班台在活動進行中的功能內容。
- 不在本次改動中加入跨裝置同步的「已顯示結果」紀錄；每個 OBS 瀏覽器工作階段獨立判定新結果。

## Decisions

### 以工作階段游標阻止歷史重播

Donate OBS 第一次完成活動讀取時，記住該活動最新抽獎紀錄的識別值而不顯示。後續輪詢只有識別值變大時才建立可視結果。這可保留資料庫與 YAML 的完整歷史，同時讓新開的 OBS 來源保持乾淨。

替代方案是刪除或標記紀錄為已讀；這會污染報表語意，且多個 OBS 來源會互相影響。

### 活動層級的顯示秒數設定

在 Donate 活動保存 `ResultDisplayDurationSeconds`，預設 15 秒並限制為 3 至 300 秒。活動層級設定符合不同抽獎活動需要不同展示節奏的使用情境，也能隨既有 CQRS 與事件溯源投影保存。

替代方案是全域 OBS 設定；這會讓不同活動共用無法調整的展示時間。

### 由共用 OBS 版面保障透明底

共用 OBS Layout 以全域 CSS 清除 html、body、app、版面容器及背景偽元素，並讓空內容保持無尺寸輸出。各 OBS 頁面的載入及找不到設定分支不渲染提示面板。

替代方案是在每個頁面重複背景覆寫；這會遺漏新 OBS 頁面並使背景行為不一致。

## Risks / Trade-offs

- [重新載入 OBS 後會略過正在顯示的舊結果] → 這是避免舊結果重播的必要結果；測試或新 Donate 可立即觸發新顯示。
- [極短秒數可能造成觀眾看不清] → 以 3 秒為最小值並在設定畫面提示用途。
- [既有 YAML 沒有新欄位] → 讀取正規化時使用 15 秒預設值，保存後寫入新欄位。

## Migration Plan

部署後，未設定顯示秒數的活動會在讀取時採用 15 秒。若要回復，可回退應用程式版本；新增 YAML 欄位會被舊版本忽略，歷史抽獎紀錄不受影響。

## Open Questions

- 無；活動層級設定、15 秒預設值與 3 至 300 秒範圍已定義。
