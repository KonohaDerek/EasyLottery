## 背景

2026-09-19 的正式站巡檢發現登入前後介面、公開隱私頁與部署設定存在可用性、可信度及上線阻礙。已登入的實際流程可載入，但支付頁顯示 Blazorise 免費版商用授權橫幅，且金流、SMTP、YouTube API 與公開回呼入口尚未完成設定。

## 目標

將可由程式碼安全修正的前端問題納入本 change，並以獨立 issue 追蹤需要授權採購、Synology 反向代理或外部服務帳號的項目。

## 範圍

- 登入頁不再預填示範 email，並在呼叫 Passkey API 前驗證必填 email。
- 公開的「關於」與「隱私權政策」使用不含管理導覽與設定 API 請求的公開版型。
- 隱私權政策改為反映 self-hosted 部署中可能保存的 Passkey、設定、活動、結果與支付回呼資料；不做法律合規保證。
- 修正文件語言、預設網站標題與缺少的頁面主標題。
- 首頁在使用者嘗試開始直播擷取前不顯示必填欄位錯誤。
- 建立 GitHub issues 追蹤 Blazorise 授權、反向代理安全與外部整合設定。

## 非目標

- 不購買或套用第三方商用授權。
- 不直接變更 Synology、DNS、反向代理、憑證、Tunnel、SMTP、金流或 YouTube 帳號設定。
- 不傳送測試支付、抽獎、通知或寫入正式資料。

## 受影響範圍

- `src/EasyLotteryWasm`：登入、路由版型、頁面語意、首頁驗證、HTML metadata、隱私內容。
- `tests`：補足前端可測試邏輯或 E2E/靜態回歸測試。
- GitHub：建立四張 issue；不在本 change 自動關閉需要人工或外部設定的 issue。

## 驗收條件

- 未登入的 `/about`、`/privacy-policy` 不呈現管理側欄，且不觸發 `/settings` 401。
- 未登入畫面不再顯示 `admin@example.com` 作為 input 值；空白 email 不會送出 Passkey 請求。
- 首頁初次載入不顯示直播網址與通關密語的驗證錯誤；使用者啟動擷取時仍會驗證。
- 根文件宣告繁中語言與 EasyLottery 標題；支付、YouTube、審計等頁面各有一個語意主標題。
- 隱私頁明確說明 self-hosted 部署者控制資料保存與外部服務使用情況，不再宣稱完全不保存資料。
- 相關測試、建置與既有測試套件通過。

## 風險與回滾

- 公開版型若遺漏必要樣式，可能影響 About/Privacy 視覺；以獨立 layout 與 E2E 截圖驗證，必要時可回復為既有 layout。
- 調整首頁驗證時機可能影響直播擷取啟動；以觸發驗證的測試保留阻擋行為。
- 隱私政策為產品文字，最終法律適用性仍需部署者審閱；可透過 revert 回復文字，但不應以舊的不實敘述作為長期方案。

## 觀測性

- 前端公開頁不應發出未授權 `/settings` 請求。
- Passkey options API 不應收到空白 email。
- GitHub issues 保留外部設定與授權項目的責任人及驗收清單。
