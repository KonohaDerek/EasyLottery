## Context

目前 Donate OBS 的通知、動畫與揭曉使用同一筆抽獎結果與階段狀態。揭曉階段沿用了通知資料卡，會與前一階段重複；無圖片的 fallback 卡又與獎項標題同時顯示，造成視覺層級混亂。活動設定尚無通知顯示開關。

## Goals / Non-Goals

**Goals:**

- 讓直播主可針對活動選擇是否顯示 Donate 資訊。
- 關閉時維持既有抽獎動畫與自動揭曉流程，但跳過通知階段。
- 讓結果階段只聚焦獎項與祝賀內容，並在有、無獎項圖片時都維持一致的可讀版面。
- 讓設定在指令、事件投影及 YAML 快照間完整往返。

**Non-Goals:**

- 不變更正式 Donate 的資格判定、抽獎機率或結果保存。
- 不新增另一套 OBS URL 或更動各動畫場景本身。

## Decisions

- 在 `DonateLotteryActivity` 新增預設為 `true` 的布林設定。使用既有活動 Aggregate payload，可避免另建設定端點並自然走既有 CQRS 與事件來源流程；舊 YAML 因模型預設值而保持相容。
- OBS 偵測到新結果時，依設定將階段設為通知或動畫。維持既有輪詢與計時器，而非由前端製造假的結果事件，確保測試與正式 Donate 使用同一路徑。
- 結果區塊不再渲染贊助明細。圖片存在時顯示圖片和獎項名稱；沒有圖片時由 fallback 卡單獨負責顯示名稱，以消除重複標題。使用固定最大寬度與合理高度範圍，避免在 OBS 不同解析度下撐滿畫面。

## Risks / Trade-offs

- [舊活動 YAML 未含新欄位] → 模型屬性初始化為 `true`，並以事件來源往返測試保障預設值。
- [關閉通知後觀眾錯過贊助資訊] → 設定標籤與說明清楚指出會直接播放動畫，預設維持開啟。
- [圖片比例差異造成結果卡不平衡] → 限制圖片與 fallback 卡的最大尺寸，並保留物件等比例呈現。

## Migration Plan

部署後，既有活動未設定欄位時沿用預設顯示 Donate 資訊；新儲存的活動會將欄位寫入事件及 YAML。若需回滾，較舊版本會忽略新增 YAML 欄位。
