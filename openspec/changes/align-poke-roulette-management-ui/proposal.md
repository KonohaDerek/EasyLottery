# 背景

戳戳樂與轉盤目前採用獨立列表、編輯器與預覽頁，操作流程與 Donate 活動的單頁 Dialog 管理方式不一致。使用者在建立、編輯、測試 OBS 與返回列表之間需要反覆切換頁面，資訊架構也不一致。

# 目標

- 將戳戳樂與轉盤的新增、編輯改為管理頁內的 Dialog。
- 列表操作與 Donate 活動一致，直接提供編輯、正式 OBS、測試 OBS 與刪除等主要操作。
- Dialog 桌面寬度至少為視窗的 75%，手機維持可用邊距。
- 保留既有模板資料、發布狀態、複製與匯入匯出能力。

# 範圍

- `src/EasyLotteryWasm/Pages/PokeBox`：戳戳樂管理頁及編輯互動。
- `src/EasyLotteryWasm/Pages/Roulette`：轉盤管理頁及編輯互動。
- OBS URL 產生與測試控制參數。
- 對應的前端建置與 Domain 回歸測試。

# 非目標

- 不改變戳戳樂與轉盤的 YAML 資料結構。
- 不改變抽獎、機率或揭露演算法。
- 不移除既有舊編輯與預覽路由，以維持既有書籤相容性。

# 驗收

- 使用者可在 `/pokebox` 與 `/roulette` 以 Dialog 新增或編輯模板，儲存後列表立即更新。
- 兩個 Dialog 在桌面至少使用 75% 視窗寬度，行動裝置不超出畫面。
- 已發布模板的列表可直接開啟正式 OBS 與帶控制介面的測試 OBS。
- 刪除前會要求確認，內建模板仍不可刪除。
- 複製與匯入匯出功能仍可使用。

# 風險

- 大型格子設定集中於 Dialog 後可能造成垂直內容較長，需使用可捲動 Modal。
- 編輯時若直接使用列表物件，取消可能污染畫面資料，因此必須深層複製編輯模型。
