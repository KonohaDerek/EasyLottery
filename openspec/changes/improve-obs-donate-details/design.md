## Context

Donate OBS 目前將中獎結果拆成獎項、祝賀文、贊助者與金額、留言、付款方式等多個同權重的文字節點。獎品圖片的高度可占用大部分畫布，讓重要的贊助內容落在首屏外；付款方式也只有未具語意的小字。既有中獎記錄已包含 `DonorName`、`Amount`、`DonationMessage` 與 `PaymentMethod`，不需要改動資料模型或 API。

## Goals / Non-Goals

**Goals:**

- 建立有標籤、可掃讀的贊助明細區，讓資訊完整顯示且有清楚層級。
- 讓文字在長內容、連續英數字、換行留言及窄視窗下自動斷行，不以裁切方式隱藏資訊。
- 控制結果內容的垂直空間，避免抽獎動畫與獎品圖片擠壓贊助者留言。
- 為 `prefers-reduced-motion` 提供低動態效果，減少 OBS 畫面的干擾。

**Non-Goals:**

- 不變更抽獎結果、Donate API、YAML 序列化或測試 Donate 的資料流。
- 不導入新的字型、UI 元件庫或影像資產。
- 不限制贊助者輸入內容或將留言以省略號截斷。

## Decisions

### 以單一語意化明細卡呈現 Donate 資訊

將贊助者、金額、付款方式與留言放在 `donate-reveal-details` 內；核心贊助者與金額維持最醒目，付款方式提供明確標籤，留言則在專用區塊保留引用樣式。這讓直播畫面能快速辨識「誰、贊助多少、如何付款、說了什麼」。

替代方案是繼續用多個文字列搭配放大字級，但無法形成可掃讀的資料關係，也會在資訊增長時繼續往下推擠。

### 以 CSS 換行與內容保護取代裁切

明細容器使用受控最大寬度、`overflow-wrap:anywhere` 與 `white-space:pre-wrap`；留言沒有固定行數或 `overflow:hidden`。圖片使用較保守的高度上限，並透過 `clamp()` 調整字級與間距，使文字在 16:9 和窄視窗中仍保有可讀大小。

替代方案是對長留言做 ellipsis 或預設折疊；這會直接違反 OBS 必須完整顯示留言的需求。

### 保持畫面資訊優先於裝飾動畫

抽獎動畫與圖片保留，但在較小高度下縮小其預留空間；明細卡會放在獎項結果之後，並以半透明深色背景提高對比。當使用者要求減少動態效果時，重複動畫會停止。

替代方案是移除動畫或圖片；這會降低既有抽獎視覺效果，且不需要為解決文字可讀性而犧牲。

## Risks / Trade-offs

- [極長文字會增加結果卡高度] → 使用彈性字級、受控的內容寬度與縮小的媒體高度保留空間，絕不裁切文字。
- [深色資訊卡可能與部分獎品圖片風格不一致] → 採半透明背景與活動色彩邊框，兼顧對比與既有主題。
- [停止動畫可能使畫面較靜態] → 僅在使用者明確設定系統減少動態效果時套用。

## Migration Plan

這是純前端展示變更，部署後新載入的 OBS 頁面立即套用。若需回復，可回退前端版本；中獎資料與 API 均未變更。
