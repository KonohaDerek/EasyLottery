## Context

Donate OBS 目前在 Razor `RefreshAsync` 中直接管理已觀察結果、通知／動畫／揭曉階段與到期時間。該實作可運作，但無法在不啟動瀏覽器與輪詢器的情況下驗證流程。動畫 class 對照也散落在頁面 switch 中。

## Goals / Non-Goals

**Goals:** 建立不依賴時間等待或瀏覽器的純狀態機，並用測試覆蓋 OBS 核心生命週期與所有動畫對照。

**Non-Goals:** 不替換 OBS 輪詢方式、不導入瀏覽器自動化套件，也不改變活動抽獎規則。

## Decisions

- 將狀態機放在 Domain，輸入活動、最新紀錄與明確的目前時間，回傳「新結果／進入揭曉／已清除」轉換資訊；這讓計時流程可在單元測試中精確驗證。
- 將動畫對照放在 Wasm 的小型目錄類別，由 Razor 消費；API 測試專案已可建置 Wasm，因此可驗證五種動畫對應。
- Razor 只負責讀取資料、呼叫狀態機與在進入揭曉時執行可選 AI 文案，維持 UI 與生命週期邏輯的單一責任。

## Risks / Trade-offs

- [重構輪詢頁面可能改變既有時序] → 使用目前行為的精確秒數與狀態作為測試案例。
- [CSS 本身無瀏覽器像素驗證] → 驗證動畫場景 key 與流程選擇；像素級視覺檢查仍由直播主在 OBS 進行。
