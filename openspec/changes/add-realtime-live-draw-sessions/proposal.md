# 背景

戳戳樂與轉盤目前由每個瀏覽器各自在前端執行抽獎。控制頁與正式 OBS 頁使用不同瀏覽器時不會同步，重新載入也無法還原進行中的狀態，而且以流水號組成的 OBS URL 容易被猜測。

# 目標

- 由 API 管理戳戳樂與轉盤的即時工作階段及唯一抽獎結果。
- 控制頁透過 REST 命令操作，OBS 頁透過 SignalR 接收同一份狀態。
- 使用不可預測的 GUID 作為公開 OBS URL。
- OBS 斷線重連或重新整理後可取得目前狀態。
- 不同工作階段的訊息彼此隔離。

# 範圍

- 戳戳樂與轉盤模板公開識別碼。
- Live Draw REST API、SignalR Hub 與伺服器端工作階段服務。
- WASM 即時用戶端及兩種 OBS 頁面整合。
- 舊整數 OBS 路由的向後相容。
- 工作階段與抽獎決策測試。

# 非目標

- 本次不重構所有模板 CRUD 為 CQRS；由後續 issue 處理。
- 本次不更換 YAML 儲存後端。
- 本次不重新設計動畫視覺。

# 驗收

- 測試控制頁操作時，正式 OBS 頁同步顯示倒數、動畫與結果。
- 每次命令只由伺服器決定一次結果，所有連線取得相同結果。
- 重新整理 OBS 頁後可還原目前結果或已揭露狀態。
- 不同 GUID 的工作階段不會收到彼此事件。
- 新產生的 OBS URL 不包含可猜測的模板流水號。

# 風險

- 即時連線可能暫時中斷，因此前端必須在重連後重新加入群組並讀取快照。
- YAML 是整份文件儲存，伺服器必須序列化變更命令以避免競爭覆寫。
