## Context

目前加班台頁面同時承擔設定、預覽與 OBS 顯示三種角色，導致直播畫面資訊過多。使用者明確希望 OBS 端只留下最必要的內容，讓觀眾聚焦在直播內容本身，而不是額外的控制卡與多筆狀態摘要。

## Goals / Non-Goals

**Goals:**
- 讓 OBS 加班頁成為單一用途的直播疊圖，未開始時只呈現預計關台時間與開始按鈕，開始後只呈現倒數文字與單行 donate 提示。
- 維持既有 donate 延長加班的規則計算，不改變金額對應邏輯。
- 讓 donate 訊息可自動消失，避免長時間覆蓋直播畫面。
- 將加班開始控制責任集中在 OBS 頁，設定頁退回配置與預覽角色。
- 將預計關台時間留在設定頁，OBS 頁的開始 / 停止按鈕負責建立與結束 session。

**Non-Goals:**
- 不重做 donate 事件來源機制。
- 不更動既有加班規則模型與金額換算公式。
- 不重新設計整體視覺主題，只調整 OBS 的資訊密度與版面配置。

## Decisions

- OBS 版面在未開始前只保留預計關台時間與開始按鈕；開始後只保留一個核心事件區與一個倒數文字。這比保留多張摘要卡更符合直播場景，能降低視覺干擾。
- donate 訊息採單行跑馬式或單列短文案呈現，避免多行文字擋住主畫面。
- donate 訊息由事件生命週期控制自動消失，避免需要人工清除。
- 加班開始與結束狀態改由 `OvertimeSupportEvent.SessionEndAtUtc` 與手動開始 / 停止事件傳遞，OBS 頁以最新事件作為倒數依據。
- 倒數文字應以最新事件攜帶的結束時間計算，開始前則顯示設定頁指定的預計關台時間。
- 示範 SuperChat / 綠界 Donate 送出時，應使用同一個 nowUtc 來寫入事件時間並套用加班延長，避免時間基準不一致。

## Risks / Trade-offs

- [Risk] 只保留單行 donate 訊息可能降低部分事件細節的可讀性 → [Mitigation] 保留必要的來源、名稱與金額/加班摘要，詳細內容仍可留在事件來源資料中。
- [Risk] 訊息自動消失時間若過短，觀眾可能看不到 → [Mitigation] 將消失秒數設為可調的設定值，並提供合理預設。
- [Risk] 將控制移到 OBS 可能讓設定頁與 OBS 頁的責任切分需要重新適應 → [Mitigation] 設定頁維持預覽，但明確移除操作區，並透過說明文字導引。
- [Risk] 若倒數文字與事件時間來源不同步，會造成畫面與狀態不一致 → [Mitigation] 使用同一份設定讀取流程與定時刷新機制。

## Migration Plan

1. 先修改資料模型或設定，加入 OBS 單行訊息的顯示秒數與必要狀態欄位。
2. 重構 OBS 頁面版型，移除控制區與多餘摘要卡，只保留倒數文字與單行訊息。
3. 將設定頁中的開始控制刪除或降級為預覽說明，保留預計關台時間與規則配置。
4. 補上測試，確認 donate 到期後會自動消失，且加班延長仍會影響倒數。
5. 以 `dotnet test EasyLottery.generated.sln` 驗證 Domain 與相關 UI 行為。

## Open Questions

- donate 訊息消失後是否要保留最後一筆摘要在某個極小角落，或完全清空？
