## Context

Donate OBS 已能接收新抽獎紀錄並在設定時間後清除，但目前把動畫、獎品與結果同時渲染。活動設定透過 CQRS、事件記錄、YAML 快照保存；新增的動畫時長必須沿用相同鏈路。動畫將以 HTML/CSS 和 inline SVG 圖形實作，避免未授權外部角色或圖片資產。

## Goals / Non-Goals

**Goals:**

- 以可重播的三階段狀態機呈現 Donate：通知、抽獎、揭曉。
- 將動畫秒數設定為 3 至 30 秒、預設 8 秒的活動設定。
- 使每種動畫在動畫階段有完整機制與角色動作，揭曉階段才顯示獎項。
- 以獎項機率、庫存與最大獎設定決定日式滾筒的球色。

**Non-Goals:**

- 不導入或宣稱包含 Live2D Cubism 模型；正式模型資產可在未來替換目前的 Q 版 CSS 角色。
- 不重新抽獎、不修改獎項機率，也不暴露尚未揭曉的獎項給 API。
- 不變更結果顯示秒數的既有行為。

## Decisions

### 以本機狀態機控制每筆結果

新結果到達後先進入通知階段，短暫顯示贊助者、金額、付款方式與留言；接著進入動畫階段，使用活動設定的動畫秒數；最後才進入揭曉階段，沿用既有結果顯示秒數。每筆中獎紀錄的 ID 作為 Razor key，確保 CSS 動畫重新啟動。

替代方案是依 CSS delay 隱藏結果；這會使流程狀態不明確，且無法可靠處理新結果與輪詢更新。

### 使用可控的原生 Q 版角色

以 SVG/CSS 的頭、身體、手臂和表情組成 Q 版角色，透過旋轉、彈跳與拉動動作模擬 Live2D 風格演出。這不需要外部網路或授權資產，也能在 OBS 離線或窄畫布中穩定運作。

替代方案是引用公開 Live2D 模型；缺少明確授權且會增加載入失敗與版權風險。

### 日式滾筒球色映射

最大獎固定金色；若無最大獎，最高權重的稀有獎項用金色。最低機率且有庫存的獎項為白色；若機率相同，剩餘數量最多者優先為白色。其他得獎依相對稀有度映射至藍、綠、黃、紅、銅或銀，並在球落下後揭曉既有中獎獎項。

## Risks / Trade-offs

- [CSS 動畫無法與正式 Live2D 模型完全一致] → 明確標示為 Q 版 Live2D 風格，並以可替換的場景結構預留資產置換點。
- [動畫時間過長使觀眾等待] → 限制 3 至 30 秒並預設 8 秒。
- [快速連續 Donate 可能覆寫前一段演出] → 最新結果優先；下一筆結果收到時重啟狀態機並展示最新通知。

## Migration Plan

舊活動讀取時套用 8 秒動畫預設值，保存後寫入新欄位。若回退，舊版本會忽略新增欄位，既有抽獎與結果紀錄不受影響。

## Open Questions

- 若提供已授權 Live2D 模型與動作檔，後續可將 Q 版角色替換為正式模型。
