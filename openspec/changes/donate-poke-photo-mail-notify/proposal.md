# 建立斗內抽拍立得特效與結果寄信功能

## 背景

目前系統已有多種斗內與互動來源，但缺少一個統一的「抽到拍立得」結果流程。直播使用時需要把不同金流與平台斗內事件接進同一套設定與觸發邏輯，並在抽中拍立得後顯示可替換的特效模板，同時把結果寄送到信箱，方便留存與後續處理。

## 目標

- 統整斗內來源設定，包含綠界、藍新、oen.tw、YouTube SuperChat、Twitch 小奇點等。
- 讓使用者可針對各來源開關啟用或停用。
- 當系統沒有對應的金流或頻道配置時，相關來源不得被勾選或啟用。
- 提供抽到拍立得時的特效模板機制，可快速更換背景與文案。
- 抽獎結果可寄送到系統設定中的信箱。
- 模板可支援 SCSS 或等效的可維護樣式方式，並可串接 AI 產生恭喜語句。

## 範圍

- 斗內來源與啟用條件的設定模型。
- 系統配置中的信箱欄位。
- 抽中拍立得後的視覺特效與模板切換。
- 模板中的背景樣式與恭喜語句配置。
- AI 生成文案的串接點與 fallback 行為。
- 與上述功能相關的 Domain、Wasm、設定頁與測試。

## 不在範圍內

- 新增未列出的其他斗內平台。
- 重做現有直播互動整體架構。
- 重新設計抽獎核心規則，除非為支援本功能所必須。
- 具體信箱服務商的專屬整合設定，除非已存在於現有系統架構內。

## 驗收標準

- [ ] 系統可在設定中分別開關綠界、藍新、oen.tw、YouTube SuperChat、Twitch 小奇點等斗內來源。
- [ ] 若某來源沒有對應的系統配置，該來源在 UI 上不得被啟用或勾選。
- [ ] 使用者可在系統配置中設定結果通知信箱。
- [ ] 抽到拍立得時會觸發可視覺化的特效呈現。
- [ ] 特效可套用至少一組模板，且模板可快速替換背景樣式與恭喜語句。
- [ ] 模板支援以 SCSS 或等效方式維護，避免修改模板時直接耦合核心邏輯。
- [ ] 抽獎結果可寄送到設定的信箱。
- [ ] 若啟用 AI 文案，模板可使用 AI 生成的恭喜語句作為內容來源之一。

## 技術約束

- 優先維持現有中文命名與 UI 風格。
- 若變更跨 Domain、Wasm 與設定頁，先以 Domain 規則與設定模型為主。
- 模板方案需保留可替換性，不把樣式硬編碼在單一頁面。
- 驗收需能透過測試或手動驗證。

## 風險與注意事項

- 來源整合範圍較廣，容易牽動多個既有事件流與設定模型。
- 若沒有先定義清楚各來源的可用條件，可能導致 UI 勾選狀態與實際可用性不一致。
- 寄信與 AI 文案屬外部依賴，需注意失敗回退與錯誤處理。
- 模板機制若設計不夠彈性，後續更換版型會變得困難。
