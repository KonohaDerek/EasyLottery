# OpenSpec Issue Template

這份模板用來在開始 worktree 與開發前，先把需求固定成可追蹤的 issue。

## 使用方式

1. 先填好背景、目標、範圍、驗收與風險。
2. 確認 checklist 沒有遺漏。
3. 使用者確認後，再建立 worktree 與開始實作。

## 標準模板

```markdown
# <issue title>

## 背景

<說明為什麼現在需要做這件事>

## 目標

- <這個 issue 要達成的主要結果>

## 範圍

- <會修改的功能、頁面、模組或流程>

## 不在範圍內

- <明確排除的內容，避免範圍膨脹>

## 驗收標準

- [ ] <可驗證的行為 1>
- [ ] <可驗證的行為 2>
- [ ] <可驗證的行為 3>

## 技術約束

- <框架、相依套件、相容性或程式風格限制>

## 風險與注意事項

- <可能的相依問題、回歸風險、資料風險>

## 開發步驟

- [ ] 確認需求與邊界
- [ ] 建立 worktree
- [ ] 實作變更
- [ ] 測試與驗證
- [ ] 整理 PR

## 備註

- <其他需要知道的資訊>
```

## 建議標準

- issue title 使用動詞開頭，讓目的清楚。
- 驗收標準要能被測試或手動驗證，不要只寫抽象描述。
- 若需求可能拆分，先拆成多個 issue，再分別進 worktree。
