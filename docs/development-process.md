# EasyLottery 開發流程

這份文件定義 EasyLottery 專案的標準開發流程。  
目標是讓每次變更都能對齊需求、可追蹤、可驗證，並在完成後順利同步。

## 流程

### 1. 需求

- 先確認要解決的問題、目標、範圍與限制。
- 如果需求不完整，先補齊資訊，不直接猜測。
- 如果需求會影響多個模組，先評估是否要拆成多個 issue。

### 2. Issue

- 先把需求整理成 issue 草案。
- issue 至少包含：
  - 背景
  - 目標
  - 範圍
  - 非目標
  - 驗收標準
  - 風險與注意事項
- 使用者確認前，不進入實作。

### 3. Worktree

- 先確認 git 狀態、目前分支與遠端資訊。
- 為每個 issue 建立獨立 worktree，避免互相干擾。
- 單一 worktree 只處理單一 issue。

### 4. 開發

- 依 issue 或 spec 逐項實作。
- 先核心邏輯，再 API、UI、設定、文件。
- 若遇到不明確處，先回到 issue 再確認。
- 不做與需求無關的大型重構。

### 5. 測試

- 先跑最相關的測試。
- 再視情況補整體驗證。
- 測試結果要能對應到驗收標準。
- 如果有手動驗證步驟，也要明確記錄。

### 6. PR

- 整理 PR title 與 description。
- PR 內容要連回 issue。
- 說明變更內容、測試結果、風險與後續事項。

### 7. 同步

- 完成後回報：
  - 做了什麼
  - 為什麼這樣做
  - 驗證了什麼
  - 還有什麼風險或待辦
- 如果有 issue 狀態、PR 狀態或文件要更新，一起同步完成。

## 這個專案的實務原則

- 優先維持現有中文說明與命名風格。
- 涉及多層級變更時，優先從 Domain 層開始。
- 所有設定檔、CI、Issue template、Copilot 指引都視為可追蹤的一部分。
- 如果變更影響測試或設定，先確認 CI 與本地驗證都能過。
